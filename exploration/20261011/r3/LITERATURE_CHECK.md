# R3执行期最近邻核查（2026-10-11，事后背景核查）

这里只核查原始论文方法与本轮支持域/对照的区别，不改变冻结实验，也不下载或复现作者框架。

| 原始文献 | 已核查的方法范围 | R3能回答与不能回答的内容 |
|---|---|---|
| [VeriRefine / A Progressive Approach to Synthesizable RTL Design Generation Using LLMs，2026-07-20](https://arxiv.org/html/2607.18519v1) | 先用逐信号ASTF明确逻辑类别、时钟及复位，审计规格解释；后续区分理解与编码错误并回送不同阶段。 | R3只给首次RTL的公开执行结果，不构建ASTF、不做理解/编码阶段定位，不验证该论文的结构化精炼收益或综合性/PPA主张。逐信号时序意图和分阶段反馈已是近邻方法，不能仅以这两个概念申报新颖性。 |
| [AutoFSM，2025-12-12](https://arxiv.org/abs/2512.11398) | 多代理、结构IR到Verilog工具链，SystemC建模/自动测试，SKT-FSM分层任务。 | R3是一次共享首次RTL、各臂再一次生成，不用IR翻译、多代理或SystemC；本机四开发家族结果不能代替SKT-FSM复现，也不能声称状态表收益。 |
| [LLM-FSM，2026-02-03](https://arxiv.org/abs/2602.07032) | 自动构造有限状态结构，再经YAML到自然语言；同YAML生成参考RTL/testbench，包含SAT及部分人工检查。 | R3以事件机制而非状态数选题，过程oracle和手写RTL不经共同YAML转换器；但共享作者/规格且仅四题，不是其千题数据规模或OOD/训练结果的可比替代。 |

上述R3比较为我们的范围判断。没有声称论文未做等调用控制，也没有核查其所有版本/消融来建立独占贡献。模型、任务、工具、预算不同，不直接横比通过率。将时序支持域变大、首次候选改为自然RTL、反馈载体改变同时发生，不能把R2到R3差异归因于单一复杂度变化。
