# 超长prompt离线传输补验协议

本轮仅离线，禁止真实Codex exec生成、登录状态/服务探测或模型请求；允许真实已安装CLI的version/help本地命令。旧root/R3/v2源码、计划、证据、成绩及默认代理回归失败保留。若原argv传输失败，建立独立r3-runner-v3，使用CLI支持的单独 `-` 参数和UTF-8文件重定向stdin，不截断或拼接候选。

固定覆盖v2验收所有16个真实构造分支prompt，包括多代码块和ASCII/UTF8候选131071/131072/131073字节的两臂。原适配器复用完整命令构造、真实Windows CreateProcess到本地接收夹具；记录成功/系统错误，不把预期传输失败丢弃。新适配器同样运行真实子进程，不mock Popen或stdin；只将CLI可执行体替换为确定Python接收夹具，并禁用真实CLI exec及网络环境。夹具必须保存接收到的全部stdin、argv及nonce收据；逐字节/SHA/长度比较输入prompt、适配器保存文件及接收内容。仅输出固定工程答案/零usage，不构成模型结果。

追加包含CRLF/LF、引号、反斜杠、中文、emoji的混合1MiB和空白负例；验证stdin EOF、进程超时树清理、输出限制、子进程非零退出及runner生成错误不重发。以新runner.generate实际入口验证所有16分支运输；来源隔离、stage/role继承v2已验证代码，不重新仿真历史RTL。

保持原环境代理，不重跑默认代理回归或覆盖其日志。新功能只能声称父进程→CLI兼容接收夹具的离线字节运输；真实CLI帮助核实stdin接口，真实模型上下文/服务接受能力仍未验证。新计划如准备必须重新放行，本轮不得启动。封存源码、输入、所有负结果及接收收据；核验历史6771绑定及新增前v2全部非缓存文件不变后提交总控。
