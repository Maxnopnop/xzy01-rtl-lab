# development-v2 预声明契约（2026-10-11）

沿用 v1 的单时钟、上升沿前采样、8bit+last、双消费者广播契约；新目录中的 checker.py 必须逐字复制 v1，未修改旧 checker/任务/成绩。输入计划独立于 DUT ready。每消费者保持顺序、恰好一次、字段相同；有效且受背压后，下一非 reset 采样必须继续 valid 且字段不变，包括 ready 释放拍。valid=0 的载荷不解释。允许同拍先接受输入再消费输出。允许输入接受前输出呈现 valid，只要不发生提前消费且背压保持成立；输出握手不能早于对应输入握手。有限窗口与公平 drain 不等价于无界活性。

同步 reset 行没有语义握手；首次 reset 取消当前 episode 尚未接受的输入以及每消费者尚未交付的已接受输入。之前已交付的事务保留账，不转入下 epoch。取消只由预声明 reset 触发，不能用于隐藏最终丢失。native reset 场景固定第8、9拍，在至少一笔已接受、consumer0已收到、consumer1仍背压时触发；后 epoch 的载荷与前 epoch 不同。原 raw reset 行也保存但不计交付。异步释放、物理恢复及采样间 glitch 不验证。

另一结构为每消费者独立深度2环形队列，统一输入只有两个队列都未满时接受，消费者可以独立出队；不要求它与共享one-slot同拍 ready/valid。人工手写 RTL 是真实 Icarus 执行对象，但不是自然模型输出、外部独立参考或R7候选。任何人工检出不能计入模型收益。

结束条件在 PROTOCOL 固定：8新native、8新手推、6比较设计语义例；执行一次新run，原失败保留，最多两次有证据的版本修复，禁止为凑通过重试。不调用模型、检索来源、扩候选、接入生产或改旧分数。
