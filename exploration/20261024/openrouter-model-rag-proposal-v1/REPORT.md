## 建议

首选三组：openai/gpt-4o-mini、openai/gpt-4.1-mini、openai/gpt-5.6-luna。前两者作为较低能力档候选，Luna 作为本项目已有 5.6 对照。采用同厂商减少一部分跨厂商差异；不能据此消除训练、推理和服务实现差异。较弱是预先提出的假设，不能用价格、发布时间直接认定 RTL 能力顺序，也不保证较弱模型更会利用资料。

公开页的 Coding Index 为 4o-mini 11.4、4.1-mini 20.2、Luna Medium 50.7（Xhigh 68.6），支持把它们列为能力梯度候选；这是通用编码而非本项目 RTL 测试，推理档也不同，不作为实验结论。本方案不是为了挑出更容易产生正增益的模型。

## 查询证据与可用性边界

本目录保存 catalog.json、selected-models.json 和三个首选模型的 endpoints JSON。access.json 记录四次无认证公开 GET 的时间、字节数与 SHA256；全部返回，零重试。只访问 /api/v1/models 及其 endpoints 元数据，没有发送 prompt 或访问生成接口。脚本使用先前已知的显式本地代理 3213；不修改或重新运行历史默认代理失败回归。

三个首选模型的公开端点列表均包含 OpenAI 与 Azure。原始 status 数值照存，不擅自赋予 SLA 含义。目录存在、提供商列出不保证本账户、地区、余额或未来调用可用；本次未验证这些事项。4.1-nano 在当前 OpenRouter 目录中出现，不把其他平台的停用消息直接套用于此路由；其端点没有额外查询。

目录 canonical_slug：4.1-mini 为 openai/gpt-4.1-mini-2025-04-14，Luna 为 openai/gpt-5.6-luna-20260709；4o-mini 未含日期。canonical_slug 是登记信息，不能未经核实就当作可请求 ID。未来冻结请求 ID、目录版本及返回模型字段；不得宣称别名保证底层权重永久固定。

## 有限对照设计（仅提案）

1. 固定用户已采用的本轮 20 题，依据 ../public-rag-all20-reconsider-v1/adoption.json；不是历史实跑 20 题。原题、测试与参考字节不变，既有 18 项排除记录及重叠/契约风险继续保留。公开题不宣称训练未见。
2. 三模型 × 有/无 RAG × 每题 2 次 × 20 题 = **240 次调用机会**，每模型 80。仅为新的待审预算提案，不继承旧预算放行，也不在旧 240 次上自动追加。若改用 Sol，应替换 Luna 后仍为 240；保留原 Luna/Terra/Sol 再加两个弱模型则为 400，当前不建议、不授权。
3. RAG 作为固定因素：同题跨模型使用逐字相同的参考片段、顺序、包装和完整消息；无 RAG 条件仅移除预声明的参考部分。检索只生成一次后冻结，禁止按模型分别检索。不改变 embedding、算法或片段以免混入第二个变量。embedding 对照仍保留为后续独立提案。
4. **待定项必须明示**：历史实跑为 18 片段 BM25；当前独立准备有 48 片段 TF-IDF 及离线算法对比。尚未把本实验最终采用的单一 RAG 包及 20 题完整上下文哈希冻结。本提案不选离线成绩“赢家”、不调参、不新生成上下文。需先明确沿用的版本，再只按其冻结规则准备同一批消息。
5. 一次调用直接生成 RTL，同一提取器和固定评测；不提供 IR、反馈、参考解或私有测试。保留编译/提取/仿真/服务失败，负增益和零增益照报。附加时序/复位等检查只在明确适用并已冻结的范围使用，不修改测试语义。
6. 预声明相同输出上限与共同支持的参数，另列推理差异。公开目录 Luna 默认 medium，4o-mini/4.1-mini 未列 reasoning；不能把同一输出上限称为相同推理计算量。建议主要比较各模型预先固定的常用配置，Luna 显式 medium，其他不发送不支持参数；参数兼容性及输出预算仍待离线核对，不能用试调用探测。若增加关闭推理条件，属于新因素，另案预算。
7. 首选固定提供商 OpenAI，禁自动 fallback；具体 provider slug 依据冻结端点数据核定。根据 OpenRouter 路由文档使用 only、allow_fallbacks:false、require_parameters:true，冻结实际请求及路由设置。禁自动模型替换、联网工具、动态 RAG、提示改写和重试。任何 403 不重复探针；UNKNOWN 占用机会并停下核账，不重发、不补样。
8. 执行前预先固定交错顺序，平衡模型与条件的先后，记录时间及服务异常，避免某模型全在另一时段。真实请求 prompt 哈希必须与冻结内容对应。零实验调用的本轮不创建预约/消耗槽位。

## 分析与判断

主指标 Δ_m = 同模型 RAG 原固定测试通过率 − 无 RAG 通过率；交互对比为 Δ_weak − Δ_5.6。不是比较不同模型的绝对成绩来判断 RAG 是否有效。

同时列每模型两条件固定机会分母、有效返回分母、双方通过/双方失败/RAG 帮助/RAG 伤害及服务不可配对数。服务失败不得包装成 RTL 错误；全机会完成成功率与有效 RTL 正确率分别报告。相同样本序号只是设计配对，不保证相同随机噪声。

20 题是主要统计单位，不把两次重复当作 40 个独立题。报告逐题差值和题目聚类的不确定性；已记录的语义重叠另做预声明敏感性展示，不删除主表中的题。每题仅两次属探索性规模，不能凭小幅正差得出确定结论，也不自动扩样。

若弱模型低基线且 Δ 更大，支持“强模型的高基线可能限制可见 RAG 增益”的解释；若弱模型也无增益，仍可能是资料、检索、上下文使用或测试敏感度问题。若弱模型更差，需照报 RAG 干扰。单次模型版本比较不能把差异完全归因于能力或发布日期，更不能推断 5.6 内置了本项目 RAG。

旧 240/96 的原成绩仅作背景，不与本轮新题组成主对照。原证据、旧版本和负结果不变。

## 费用提案

最终上限需冻结完整消息、输出/推理 token 上限及端点价格后计算。本次不读取余额、不购买、不授权付费。

仅作量级示例：每请求假设平均输入 3000、计费输出（含可能的推理）2000 token，每模型 80 次，则 4o-mini $0.132、4.1-mini $0.352、Luna $0.240，总计 $0.724。不是测得长度、硬上限或正式预算；RAG 与无 RAG 实际输入长度不同。Sol 替换 Luna 时同假设总额 $4.644。失败/未知账单照存，不能假定失败免费。
