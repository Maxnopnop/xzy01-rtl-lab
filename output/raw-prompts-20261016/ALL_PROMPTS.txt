USER PROMPT: rt_sequence

Please act as a professional Verilog designer.

Implement a module of a sequence detector to detect a specific 4-bit binary sequence 1001.

Module name:
    sequence_detector

Input ports:
    clk: Clock signal to synchronize the detector.
    rst_n: Active-low reset signal to initialize the state machine.
    data_in: 1-bit binary input signal to feed the bitstream for sequence detection.

Output ports:
    sequence_detected: 1-bit output signal that is set high when the specific sequence is detected.
    
Internal logic:
    State Machine: The sequence detector uses a finite state machine (FSM) with the following states:
    IDLE: Waiting for the start of the sequence.
    S1: The first bit of the desired sequence is detected.
    S2: The second bit of the desired sequence is detected.
    S3: The third bit of the desired sequence is detected.
    S4: The fourth and final bit of the desired sequence is detected, and the output sequence_detected is set high.

Implementation:
    -FSM Design: The FSM transitions through states based on the bitstream data_in. On each clock cycle, the detector checks for a match of the specific sequence.

    -Sequence Detection: The module checks the input data_in and transitions between states. Once the complete sequence is detected, sequence_detected is asserted.

    -Reset Behavior: When rst_n is low, the state machine returns to the IDLE state, resetting the detection process.

Development-subset clarification (part of the fixed specification): Use asynchronous active-low reset, overlapping detections, and a Moore output high after the edge consuming the final 1; matching the archived reference.


USER PROMPT: sticky_alarm

Implement module sticky_alarm(input clk, input rst_n, input din, output q). Use rising clock edges, asynchronous active-low reset, and Moore outputs. q starts at 0. Two consecutive sampled ones set q to 1. Once set, q remains 1 until reset, regardless of later input. A zero before activation breaks the consecutive-one count.


USER PROMPT: event_parity

Implement module event_parity(input clk, input rst_n, input din, output q). Use rising clock edges, asynchronous active-low reset, and Moore outputs. q starts at 0. On each rising clock edge with din=1, toggle q. With din=0 hold q. Thus q is the parity of the number of sampled ones since reset.


USER PROMPT: request_delay

Implement module request_delay(input clk, input rst_n, input din, output q). Use rising clock edges, asynchronous active-low reset, and Moore outputs. Initially idle with q=0. In idle, a sampled din=1 accepts a request. q remains 0 on that accepting edge, then is 1 for exactly the following clock cycle, regardless of din. At the next edge q returns to 0 and enters cooldown. In cooldown, remain there while din=1; an edge with din=0 returns to idle. The edge returning to idle does not accept a request.


USER PROMPT: debounce3

Implement module debounce3(input clk, input rst_n, input din, output q). Use rising clock edges, asynchronous active-low reset, and Moore outputs. Initially q=0. While q=0, require three consecutive sampled ones to change q to 1 on the third edge; any zero restarts this count. While q=1, require two consecutive sampled zeros to change q to 0 on the second edge; any one restarts this count. q otherwise holds.
