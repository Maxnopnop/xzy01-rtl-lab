# 总控验收标准（执行前声明）

## RAG与选题
1. 方法设计依据不得引用考题/答案/成绩/失败或命中情况；不是把已看题转开发集便可调优。记录已知认知暴露局限。
2. 一般文档来源可溯源、原文/许可/分段/检索/参数/消息包装都有哈希；不混入benchmark解答和测试。
3. A方法冻结在B候选读取之前；B、C结束重算A全锁一致。固定候选顺序与筛选分母，不依检索排名选题，最多20候选、最多8入选。
4. 历史ID/文件hash及语义近重复去重；原题/TB/ref不改。含糊或参考不合格排除，参考同源如实标识而非独立oracle。
5. 同题同条件三模型实际messages相同；题目只通过原文自动检索。请求模型固定、2臂×3模型×2样本，最多96待审，不调用模型。

## 控制台
1. 可直接打开的入口与实际控件；旧冻结源码不改，源码hash前后核对。
2. OpenRouter生成明确包含在功能中；区别生成按钮/真实网络请求/已验证的历史API与本轮离线模拟。请求必须显式model，禁止fallback/retry；三模型同条件字节比较。
3. key隐藏输入、仅进程内传递，不写配置/日志/命令行；错误信息脱敏，关闭/执行后清除可清除引用，不声称Python字符串可安全擦除内存。
4. 先预览冻结批次；未审批、不完整seal、超调用上限、已预约/已完成/失败/unknown槽均拒绝生成，不靠禁用按钮替代后端门禁。
5. 导入旧240及新96记录，显示原失败/服务失败/规格限制与token；完成批次不自动再次生成。
6. 原RTL绑定原TB/ref，本机Icarus和Yosys阶段分开，评分与综合分别存证；不可把综合PASS替代功能PASS。有界/不支持情况明确。
7. 学校只选择单案例打包、命令和回收，文件齐全校验，SHA绑定，不含库/凭据；不得自动学校批处理。
8. slot25 CHECK_COUNT_DIFFERENT维持，展示211/212及原213，不追改PASS。库单位/无SDF/同源参考局限保留。
9. 离线真实请求capture、失败单POST、预算/未知状态防重、输入锁、防密钥落盘测试；一例本机工具适配验收。隐藏Tk测试不冒充真人点击验收。
